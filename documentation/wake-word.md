# "Hey Waldo" wake word

Labels: `team-reported` = stated by the team, no measurement stored in this repo. `host` = laptop test. `UNVERIFIED` = not tested.

**Status: removed from the shipped build (team decision, 2026-10-18).** It never ran in the final board image. This repository keeps the code and the
training scripts, but **no wake-word metric (false alarms per hour, miss rate, latency)** and **not the trained model**:
`he/wake_pte_he.c` and `he/test_wake.h` are generated by `model/wake/export_wake.py` and are not committed, and
`he/wake-hooks.patch` (the hooks into the HE image) is not applied to the tree. Numbers belong here once the run that produced them is committed.

## How it works

- A second small ExecuTorch program on the HE's Ethos-U55-128, beside MicroNet-M. Same input: the 49 x 10 MFCC window of the last 1 s
  ([he/wake.hpp](../he/wake.hpp), [he/wake.cpp](../he/wake.cpp)).
- It runs once per 200 ms window. A debounce fires an event when at least `k_hits` of the last `n_window` windows score at or above the
  threshold, then ignores further events for a refractory period ([he/wake_debounce.h](../he/wake_debounce.h)). Configured values:
  `n_window` 3, `k_hits` 2, refractory 2.0 s; the threshold is the lowest validation value with at most 1 false alarm per hour
  ([model/wake/config.yaml](../model/wake/config.yaml)).
- The HE posts the event to the mailbox; the HP opens a 5 s listening window (`orch_wake`, `orch_set_wake_required`). **stop** and **off** never need it
  ([voice-commands.md](voice-commands.md)).
- Training data: synthetic voices (macOS TTS) and Speech Commands negatives, an optional real-voice set from `record_real.py`.
  The licence of using macOS TTS output for training is UNVERIFIED. Scripts and seeds: [model/wake/](../model/wake/).
